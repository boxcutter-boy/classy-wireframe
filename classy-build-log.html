Product decisions & UX rationale

Classy — Build Log

A running record of what got built and why — a blind dating app where people meet through written personal ads instead of photos, dressed as a newspaper's classifieds.

Dates through Jul 16 are from the wireframe's git history and file saves. The Figma / Material 3 work is dated approximately (~Jul 18–23) — those changes happened in Figma and don't carry timestamps.

The bets everything rests on

◆
Blind & text-first — you meet through writing, not a face. The core differentiator.
◆
Classifieds as identity — the paper, Personals, horoscope, issue date. Not chrome, it's the concept.
◆
Consent-gated reveal — faces appear only by mutual opt-in, never one-sided.
◆
Reciprocity — you must post your own ad to read the paper. Everyone's in it.
◆
Personal expression — your ad, your fonts. The one place members style their own type.
◆
Legibility as a right — one toggle flattens every decorative font to a plain, readable one.

Phase II · Rebuilding on Material 3

~Jul 18–20 · approximate
~Jul 18–20

Color system

  • Reskinned M3 color styles AND variables to the Classy palettecomponents read styles, styles must trace to variables, so both had to move
  • Two-tier cream: #F2EAD3 base · #FCF7EA cards/newspaper · #F7F1DF replied-carddepth and hierarchy within the cream instead of one flat tone
  • Text fields → white; warmed the dark-mode greysinput clarity; kill the cold blue undertone so dark mode matches the warm palette
  • Bound styles → variables so the native dark-mode (variable modes) toggle worksone switch actually flips the whole document
~Jul 18–20

Typography

  • Brand = Clarendon URW, Plain = ITC Franklin Gothicmaps cleanly onto M3's built-in brand/plain two-typeface model
  • Brand on Display + Headline; Plain on Title / Body / LabelM3's default split — and it fits Classy exactly
  • One deviation: Brand pushed into Title Large (section headers, card/person names like "Riley")headings carry the editorial personality; keep smaller titles utilitarian
  • Set via the Font theme variables (both modes)two edits re-skin the whole document's type
  • Ad fonts stay member-chosenthe deliberate exception — self-expression on the personal ad
~Jul 18–20

Shape & buttons

  • Buttons: square shape, radius 8, square as defaultgeometric, editorial look over M3's default pills
  • Corner radius 8 globally via a Scripter sweepthe Shape variables aren't wired to components (hardcoded radii), so variables alone couldn't do it
  • Vertical trim → "Cap height to baseline" on labelsClarendon's caps floated high in buttons; trim re-centers them
~Jul 20

Process decision

  • Chose to duplicate the M3 file (build the app inside a copy) instead of publishing it as a libraryvariable publishing needs Org/Enterprise; on Professional, duplicating keeps the whole variable system intact with zero sync friction

Phase III · The mobile wireframe

Prototype · approximate
~Jul 21

The home feed becomes a paper you browse

  • Feed opens as a pan-and-zoom classifieds page, started slightly zoomed incommit fully to the newspaper metaphor — wander the page like a real paper instead of scrolling a feed; the crop invites you to look around
  • 25 personals an issue, set in five columns, closing on an "End of today's paper" marka finite, curated daily issue — scarcity and a sense of closure over an endless feed
  • Kept a single-column reading list as a togglethe dense paper is for browsing; the list is for actually reading — two intents, two views
  • Built as its own mobile-first file, not responsive tweaks to the desktopmobile changes navigation and interaction enough that a responsive layer would fight the approved desktop prototype
~Jul 21

Mobile navigation & focus

  • Charcoal sidebar → bottom tab bar (Feed · My Ad · Messages · Settings)thumb-reachable, the expected mobile home
  • Reading an ad and the face reveal open as centered cards; edit forms stay bottom sheetsthe "moments" get the spotlight; routine editing stays lightweight and dismissible
~Jul 21

The ad card, restyled

  • Decorative font now only on the name + age; the headline goes ALL CAPS in the body font, so headline and body share one facepersonality lives in the name; one readable typeface keeps 25 ads legible and true to a real classifieds page
  • "Build" dropdown → a free-text "Appearance" write-in ("tall, glasses, goth")describe yourself in words, not categories — consistent with the no-photos premise; a body-type radio felt clinical and off-brand
  • Forced all dark-mode text to white / light greylegibility as a right — removed low-contrast colored text (the required-field red was illegible on dark)
~Jul 21

The conversation & the reveal

  • Face-reveal prompt moved into the conversation body; the thread header now names the personthe reveal is a moment in the chat, and a name makes it feel like talking to someone, not managing a thread
  • Once both reveal, a small eye icon marks the conversationa quiet, persistent sign you've crossed that line together
  • Reveal became press-and-hold on touch, fogging back when you let gomakes seeing a face a deliberate, physical act on mobile (was hover-to-peek on desktop)

Phase IV · Component system & tokens

~Jul 22 · approximate
~Jul 22

The desktop sidebar, rebuilt on auto layout

  • Nav built as one vertical auto-layout column set to space-betweenpins the logo to the top and the account block to the bottom; the middle gap absorbs any height change, so it's vertically responsive for free
  • App shell = a horizontal flex row (fixed-width sidebar + fill content)mirrors how a dev builds it (display:flex), so Dev Mode reads 1:1 and handoff stays clean
  • Componentized the atoms — Nav Item with a State variant, Logo/Master nested inside LogoBlockedit once, propagate everywhere; layout frames stay plain frames, not components
~Jul 22

A sidebar token extension on top of M3

  • Added a small sidebar/* group (surface, on-active, on-inactive, divider) sharing the same primitivesM3 has no semantic slot for a dark rail that must stay darker than content in both modes
  • sidebar/surface flips #404043 (light app) → #26262C (dark app)the sidebar is always the darker neighbor of the content beside it
  • Active/inactive is a component State variant, not a variable modeone active + several inactive items coexist in the same frame, which a mode (one value per frame) can't express
~Jul 22

Palette finalized — monochrome

  • Dropped the lavender accent as leftover Materialthe identity is charcoal-on-cream contrast and the serif wordmark, not a color
  • Brick reserved as semantic-only — danger buttons and notification dotskeep semantic color quarantined; Classy carries no decorative accent by design
  • Locked a warm-neutral ramp, Ink #26262C → Paper #FCF7EA, named by toneone primitive foundation feeding both the M3 roles and the sidebar extension
~Jul 22

The style → variable migration

  • Found the components were wired to paint styles (M3/sys/light/*), not variablesstyles have no modes, so flipping the page mode did nothing until they were migrated
  • Hand-set the neutrals instead of trusting Material Theme Buildera near-hueless charcoal seed leaves HCT no hue to build from, so it defaulted the whole palette to blue
  • Trimmed the auto-generated modes down to Light + Darkthe medium / high-contrast modes were noise for this project
  • Ran a scoped, match-by-name style→variable migration per pageonly the pages actually used need it; the full-kit sweep (79k nodes) was slow and overkill
~Jul 23

Reskinning the components — buttons first

  • Cut the button set to Filled, Outline, Text — dropped Tonal, Elevated, and every Toggle variantan MVP needs the components the product actually uses, not Material's whole catalog; a lean set reads as intentional and slims the file
  • Disabled states became dedicated tokens with the alpha baked ina fill bound to a variable can't carry its own opacity, so the fade has to live inside the token
  • Left the hover/press "state layers" on their styles during the link passtheir opacity is baked into the style — swap it for a solid variable and a faint tint becomes a solid block
  • Drove state backgrounds through the fill, never layer opacitythe label sits inside the state layer, so zeroing the layer's opacity hid the label with it
  • Gave the text button its own state tokens — a warm chip on hover, a muted grey when disabledMaterial's default tint is nearly invisible; a defined background reads as deliberate
~Jul 23

Text field — rebuilt from scratch

  • Abandoned the M3 text field and rebuilt it — label above a fully-closed rounded rectangle, no notched outlineM3's notched-outline field fought the editorial look; the wireframe wants a plain closed box, and reskinning the original was messier than starting clean
  • Made the input text Fill-container width + Hug height, field Hugs heighttext wraps inside the box and the field grows for multi-line inputs (the ad description) instead of overflowing
  • Optional parts became boolean properties, not variants — leading checkbox, counter, label toggle independentlyvariants are for mutually-exclusive states; toggle-able parts as booleans avoid a combinatorial explosion of variant rows
  • State (Enabled / Focused / Error / Disabled) reserved for the variant axisthose never coexist on one field, so they're the correct thing to model as variants — reusing the existing tokens

Phase V · Building past the kit

~Jul 24–26 · approximate
~Jul 24–26

A rule for reskin vs. rebuild

  • Reskin the Material component only when it's the same anatomy in different paint; build from scratch when the anatomy itself differsreskinning a mismatched component means deleting and fighting more than you keep — the message cards and the menu were faster to build than to un-build M3's
  • "From scratch" still composes from existing tokens + button / checkbox components, never raw ad-hoc shapeskeeps bespoke pieces inside the system, so they inherit dark mode and stay consistent
~Jul 24–26

Message cards, built from scratch

  • Conversation preview and ad-response are one card, with a Bottom Row boolean that reveals the Decline / Accept footerthey share a header and body; a single toggle beats maintaining two near-duplicate components
  • Reused the Filled + Outline buttons for the actions; the unread signal is one dot on a booleanreuse over rebuild, and the dot is the only read / unread cue the design needs
  • Added a dedicated caption text token because On Surface Variant read too dark in dark modethe M3 roles had no slot at the right contrast for the muted ad-tagline line
~Jul 24–26

The settings list

  • One row set swaps trailing type via a variant — switch / button / link / danger / menu — where Danger also reddens the headingDanger is a row-level treatment, so a variant carries it cleanly; a trailing instance-swap alone couldn't recolor the heading
  • Stacked rows sit in a container that owns the radius and clips its content, so only the group's outer corners roundone container rounds any number of rows correctly, and a single-row group comes out fully rounded for free
  • Hairline dividers are a 1px gap revealing the container fill; the line uses Outline Variant, not Outlineno per-row divider bookkeeping, and plain Outline washed out in dark mode
~Jul 26–27

Dialogs — two families, not one

  • Split confirmations and the face-reveal into two separate component familiesthe face-reveal carries its own Show / Trade / Offer state axis that would clash with a confirm/reveal axis on a shared component
  • Decline / Block / Unmatch differ only in text (+ Decline's optional "also block" checkbox), so they're one shell reused, not three componentscontent isn't structure — a variant per message string is the explosion trap
  • Confirmations reuse the danger + outline buttons; desktop centers them, mobile will float the same payload as a bottom sheeta dialog and a bottom sheet are one content block in two containers, so they shouldn't be built twice
~Jul 26–27

The destructive button

  • "Error" is its own axis (emphasis), never a value inside Statea destructive button still gets hovered, pressed, and disabled — folding error into State throws those states away
  • Built as a lean dedicated Danger set (only the sizes/states actually used), not a colour axis doubling the whole button catalogueClassy uses the destructive button in one style only; matches the earlier decision to trim the button set to what the product uses
~Jul 27

Screen headers & a voice call

  • The screen header is an editorial masthead — serif title + "ISSUE DATE {date}" — on its own header/* surface tokensthe header bar is a distinct surface in both modes, like the sidebar rail; no stock M3 role fit it
  • Nav labels and page titles deliberately use different registers (sidebar "Feed" → header "Today's Picks")terse destinations vs. editorial titles — two systems doing two jobs
  • But aligned the possessive voice: sidebar "My Ad" → "Your Ad" to match "Your Messages"wording can differ between nav and title, but flipping person on the same feature — both on screen at once — reads as an oversight; second person is the modern convention and Classy's established voice
